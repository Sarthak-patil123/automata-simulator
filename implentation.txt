# Implementation Plan: Automata Learning Studio
*Algorithm decision + full fix & build plan — ready for execution*

---

## Core Architecture Decision

> **Expose ONE algorithm to the user. Internally, L\* with HITL is the engine.**

### What the User Sees
```
[Generate DFA]  →  instant graph (RPNI warm-start)  →  "Improve Accuracy" (L* HITL)
[Generate NFA]  →  NFA graph (NFA Learner)
```

### What Runs Internally (Hidden from User)
```
DFA path:
  Step 1: Run RPNI on CSV  → first-pass DFA (shown immediately, ~80–100% accurate)
  Step 2: L* uses RPNI result as first conjecture
  Step 3: HITL panel asks user yes/no for uncertain strings
  Step 4: Final minimal DFA at 100% accuracy

NFA path:
  Single step: NFA Learner on CSV → compact NFA graph
```

### What Gets Removed
- ❌ Algorithm selector dropdown (RPNI / EDSM / L* / NFA as user choice)
- ❌ EDSM as a separate user-visible mode
- ❌ Orphaned `csvPreprocessor.js`
- ❌ Hardcoded `fallbackModel()` fake graph
- ❌ Duplicate CSV parser (unify to one)

### What Gets Kept (Internally)
- ✅ RPNI — internal warm-start before L*
- ✅ L* — the main learning engine for DFA
- ✅ NFA Learner — for NFA output type
- ✅ EDSM — available internally if RPNI warm-start fails

#### Fix 2.2: Arrow Endpoint Offset (stops arrows from hiding inside node circles)
```js
// Currently arrows point to node center; they overlap the circle
// Fix: shorten path to stop at the circle boundary (radius ≈ 22px)
function shortenPath(src, tgt, r = 22) {
  const dx = tgt.x - src.x, dy = tgt.y - src.y;
  const dist = Math.sqrt(dx*dx + dy*dy);
  return { x: tgt.x - (dx/dist)*r, y: tgt.y - (dy/dist)*r };
}
```

### Phase 3 — Backend: L\* + CSV Oracle Integration (~2–3 hours)
*Makes L\* work without a reference DFA — the accuracy unlock.*

#### Fix 3.1: Modify `AutomataMLService.train_model()` in `api.py`

**Current (broken for CSV):**
```python
if algorithm == "lstar":
    if ref_dfa is None:
        raise ValueError("L* active learning requires a reference oracle or preset index.")
```

**New (CSV-oracle fallback):**
```python
if algorithm == "lstar":
    # Build a lookup oracle from the CSV labels
    label_lookup = {s: True for s in positive_strings}
    label_lookup.update({s: False for s in negative_strings})
    
    def csv_membership_oracle(w: str) -> bool:
        if w in label_lookup:
            return label_lookup[w]
        # Unknown string: pessimistically reject
        # (HITL session will ask user about truly uncertain ones)
        return False
    
    teacher = Teacher(
        membership_oracle=csv_membership_oracle,
        reference_dfa=ref_dfa  # None if no preset; L* uses RPNI equiv check
    )
    
    # Use RPNI result as the first conjecture (warm-start)
    rpni_result = RPNILearner(positive_strings, negative_strings, alphabet).learn()
    rpni_dfa = rpni_result["inferred_dfa"]
    
    # Equivalence oracle: compare against RPNI model, 
    # then route discrepancies to HITL
    def equiv_oracle(conjectured: DFA):
        is_eq, ce = are_equivalent(conjectured, rpni_dfa)
        return is_eq, ce
    
    teacher.equivalence_oracle = equiv_oracle if ref_dfa is None else None
    learner = LStarLearner(alphabet=alphabet, teacher=teacher)
    learner.seed_from_examples(positive_strings + negative_strings)
    res = learner.learn()
    # ... rest as before
```

#### Implementation in `index.html`

```jsx
// New state variables
const [hitlMode, setHitlMode] = useState('idle');  
// 'idle' | 'querying' | 'conjecture_ready' | 'converged'
const [hitlQuery, setHitlQuery] = useState(null);
// { query_string, prompt, total_queries_asked }
const [hitlConjecture, setHitlConjecture] = useState(null);
const [counterexampleInput, setCounterexampleInput] = useState('');
const [hitlQueryCount, setHitlQueryCount] = useState(0);

// Start HITL session
async function startHITL() {
  const res = await fetch('/api/active/start', {
    method: 'POST',
    body: JSON.stringify({
      alphabet: preprocessed.alphabet,
      initial_positive: preprocessed.positiveStrings,
      initial_negative: preprocessed.negativeStrings,
    })
  });
  const data = await res.json();
  handleHITLStep(data);
}

// Route HITL response to correct UI state
function handleHITLStep(data) {
  if (data.status === 'NEED_MEMBERSHIP_QUERY') {
    setHitlMode('querying');
    setHitlQuery(data);
  } else if (data.status === 'CONJECTURE_READY') {
    setHitlMode('conjecture_ready');
    setHitlConjecture(data);
    // Update graph to show current conjecture
    prepareGraphPositions(data.conjectured_dfa);
    setGraphData(data.conjectured_dfa);
  } else if (data.status === 'CONVERGED') {
    setHitlMode('converged');
    prepareGraphPositions(data.final_dfa);
    setGraphData(data.final_dfa);
  }
}

// Answer yes/no
async function answerHITL(accepted) {
  setHitlQueryCount(c => c + 1);
  const res = await fetch('/api/active/answer', {
    method: 'POST',
    body: JSON.stringify({ is_accepted: accepted })
  });
  handleHITLStep(await res.json());
}

// Confirm conjecture
async function confirmConjecture(counterexample = null) {
  const res = await fetch('/api/active/confirm', {
    method: 'POST',
    body: JSON.stringify({ counterexample })
  });
  handleHITLStep(await res.json());
}
```

The Algorithm Selector Question

Short answer: Yes, reduce to one. Use L* with HITL.

Here's the reasoning:

Why Multiple Algorithms is Wrong for This Problem

The problem statement says:

"Develop or integrate an automata-inference algorithm" (singular) ML technique: Active learning (not passive) "Model will ask whether given string passes or not" — that's literally L*'s membership query

RPNI, EDSM, and NFA Learner are all passive algorithms. They can only work with what the user gave them. They can't ask questions. They can't reach 100% on sparse data.

The Benchmark Already Tells You
Algorithm	8-node DFA from sparse CSV	Requires oracle?
RPNI	❌ 80–89%	No
EDSM	❌ ~89%	No
L* (automated)	✅ 100%	Yes — needs reference DFA
L* + HITL	✅ 100%	User is the oracle ← this is what you want
NFA Learner	varies	No
The Clean Architecture (One Algorithm)
User CSV
   │
   ▼
RPNI runs instantly  ──────────────────────────┐
(warm-start, uses CSV labels as oracle)        │
   │                                           │
   ▼                                           ▼
L* gets RPNI result as                  Graph shown immediately
first conjecture                        (best passive guess)
   │
   ▼
L* identifies strings it's
uncertain about (outside CSV)
   │
   ▼
HITL Panel asks user
"Is '1010' accepted? Yes/No"
   │
   ▼
L* refines model
   │
   ▼
When user confirms conjecture
→ 100% minimal DFA ✅

RPNI still lives — but as an internal warm-start step, not a user choice. The user never sees "pick RPNI or EDSM." They just see "Generate DFA" → immediate graph → then optional "Improve with AI questions" mode.

Does Keeping NFA make sense?

Yes — but as a separate output type, not a competing algorithm. When user clicks "Generate NFA", you use the NFA Learner internally. When they click "Generate DFA", you use L*+HITL. That's a machine type selector, not an algorithm selector — which is what your UI already correctly shows
